🔐 Lab: IPsec Site-to-Site VPN in PNETLab

Lab operativo CCNA/SNOC: configurazione di un tunnel IPsec Site-to-Site tra due router Cisco, con OSPF over GRE per trasportare il traffico di routing, e simulazione di guasto per analisi dei log.

🎯 Obiettivi del Lab:
1. Configurare un tunnel IPsec IKEv1 Site-to-Site tra R1 e R2.
2. Incapsulare OSPF in un tunnel GRE sopra IPsec.
3. Verificare la connettività end-to-end con show e debug.
4. Simulare un guasto e leggere i log di errore come farebbe uno SNOC analyst.

⚙️ FASE 1 — Configurazione Base (Pre-VPN)

1Configurazione R1

! --- R1 Base Config ---
hostname R1
!

ip route 0.0.0.0 0.0.0.0 10.0.0.2

2Configurazione R2

! --- R2 Base Config ---
hostname R2
!

!
interface GigabitEthernet0/0

⚠️ Verifica prima di procedere:
Esegui ping 10.0.0.2 da R1. Se il ping fallisce, non continuare — il tunnel IPsec non può formarsi senza connettività WAN di base.

🔑 FASE 2 — IKE Phase 1 (ISAKMP Policy)

IKE Phase 1 crea il canale sicuro di controllo tra i due peer. I parametri devono essere identici su entrambi i router.

3ISAKMP Policy su R1 e R2 (stesso config)

! --- IKE Phase 1 Policy (uguale su R1 e R2) ---
crypto isakmp policy 10
 encryption aes 256
 hash sha256
 authentication pre-share
 group 14
 lifetime 86400
!
! Pre-Shared Key (uguale su entrambi, ma con IP del PEER)
! Su R1:
crypto isakmp key CCNA_VPN_KEY address 10.0.0.2
! Su R2:
crypto isakmp key CCNA_VPN_KEY address 10.0.0.1
ParametroValore sceltoSignificato
encryptionAES-256Cifratura simmetrica del canale
hashSHA-256Integrità dei messaggi IKE
authenticationpre-shareAutenticazione via PSK
group14 (2048-bit DH)Diffie-Hellman Key Exchange
lifetime86400 sec (24h)Durata della SA di controllo

🔒 FASE 3 — IPsec Phase 2 (Transform Set + Crypto Map)

4Transform Set e ACL (uguale su R1 e R2)

! --- Transform Set: definisce come cifrare i dati ---
crypto ipsec transform-set CCNA_TS esp-aes 256 esp-sha256-hmac
 mode tunnel
!
! --- ACL: definisce quale traffico va nel tunnel ---
! Su R1: traffico da HQ a Branch
ip access-list extended VPN_TRAFFIC
 permit ip 192.168.1.0 0.0.0.255 192.168.2.0 0.0.0.255
!
! Su R2: traffico da Branch a HQ (mirror)
ip access-list extended VPN_TRAFFIC
 permit ip 192.168.2.0 0.0.0.255 192.168.1.0 0.0.0.255

5Crypto Map e applicazione all'interfaccia

! --- Crypto Map (su R1) ---
crypto map CCNA_VPN_MAP 10 ipsec-isakmp
 set peer 10.0.0.2
 set transform-set CCNA_TS
 match address VPN_TRAFFIC
!
! --- Applica la crypto map all'interfaccia WAN di R1 ---
interface GigabitEthernet0/1
 crypto map CCNA_VPN_MAP

! === RIPETERE SU R2 con IP peer 10.0.0.1 ===
crypto map CCNA_VPN_MAP 10 ipsec-isakmp
 set peer 10.0.0.1
 set transform-set CCNA_TS
 match address VPN_TRAFFIC
!
interface GigabitEthernet0/1
 crypto map CCNA_VPN_MAP

🔍 FASE 4 — Verifica e Troubleshooting (SNOC Skills)

6Attivare il tunnel (trigger)

Il tunnel IPsec non si attiva automaticamente: si attiva solo quando passa traffico interessante (quello matchato dalla ACL). Genera traffico con un ping da PC-HQ verso PC-Branch. 
! Da PC-HQ (o simulato da R1):
ping 192.168.2.10 source 192.168.1.1 repeat 5

7Show Commands — Verifica Fase 1

show crypto isakmp sa

Output atteso (tunnel UP):

dst             src             state          conn-id status
10.0.0.2        10.0.0.1        QM_IDLE           1001 ACTIVE
🚨 Se vedi MM_NO_STATE o AM_ACTIVE con errori: mismatch nella ISAKMP policy o nella PSK. Controlla che i parametri siano identici su entrambi i peer.

8Show Commands — Verifica Fase 2

show crypto ipsec sa

Cerca nel output i contatori #pkts encaps e #pkts decaps. Se crescono, il traffico scorre nel tunnel.

#pkts encaps: 5, #pkts encrypt: 5, #pkts digest: 5
#pkts decaps: 5, #pkts decrypt: 5, #pkts verify: 5

9Debug — Analisi Negoziazione

⚠️ Attenzione: I debug generano molto output. Usali in ambienti lab, mai in produzione senza autorizzazione. Disattiva sempre con undebug all dopo l'analisi. 
! Abilita debug IKE
debug crypto isakmp
debug crypto ipsec

! Genera traffico per triggerare il debug
ping 192.168.2.10 source 192.168.1.1

! Disabilita dopo l'analisi
undebug all

🌐 BONUS — GRE over IPsec (OSPF nel tunnel)

GRE permette di trasportare protocolli di routing (come OSPF) all'interno del tunnel IPsec. Il GRE "avvolge" il pacchetto OSPF, e IPsec cripta il tutto.

Configurazione Tunnel GRE (R1)

! --- Tunnel GRE su R1 ---
interface Tunnel0
 ip address 172.16.0.1 255.255.255.252
 tunnel source GigabitEthernet0/1
 tunnel destination 10.0.0.2
 no shutdown

Configurazione Tunnel GRE (R2)

! --- Tunnel GRE su R2 ---
interface Tunnel0
 ip address 172.16.0.2 255.255.255.252
 tunnel source GigabitEthernet0/1
 tunnel destination 10.0.0.1
 no shutdown

OSPF sopra il Tunnel GRE

! --- OSPF su R1 ---
router ospf 1
 network 192.168.1.0 0.0.0.255 area 0
 network 172.16.0.0 0.0.0.3 area 0

! --- OSPF su R2 ---
router ospf 1
 network 192.168.2.0 0.0.0.255 area 0
 network 172.16.0.0 0.0.0.3 area 0
⚠️ Aggiorna la Crypto ACL per GRE over IPsec:
Con GRE, il traffico interessante non è più IP src/dst ma il protocollo GRE stesso. 
! Su R1 — modifica ACL per matchare il traffico GRE
ip access-list extended VPN_TRAFFIC
 no permit ip 192.168.1.0 0.0.0.255 192.168.2.0 0.0.0.255
 permit gre host 10.0.0.1 host 10.0.0.2

🚨 FASE 5 — Simulazione Guasto (SNOC Drill)

Scenario: il tunnel VPN cade improvvisamente. Come reagisce uno SNOC analyst?

Simula il guasto

! Su R2 — cambia la PSK (simula mismatch di configurazione)
crypto isakmp key WRONG_KEY address 10.0.0.1
! Oppure abbatti il tunnel esistente:
clear crypto isakmp

Procedura di Triage SNOC

StepComandoCosa cerchi
1. Verifica Layer 3ping 10.0.0.2Se fallisce, problema WAN — non IPsec
2. Stato IKEshow crypto isakmp saQM_IDLE = OK, MM_NO_STATE = problema Phase 1
3. Stato IPsecshow crypto ipsec sapkts encaps/decaps fermi = tunnel giù
4. Debug IKEdebug crypto isakmpMessaggio di errore specifico (auth, atts, ecc.)
5. Fix e Resetclear crypto isakmp / clear crypto saForza rinegoziazione dopo fix
✅ Lab Completato con successo se:
• show crypto isakmp sa → stato QM_IDLE
• show crypto ipsec sa → contatori pkts encaps/decaps > 0
• ping 192.168.2.10 source 192.168.1.1 → 5/5 success
• show ip ospf neighbor → vicino OSPF visibile tramite Tunnel0
