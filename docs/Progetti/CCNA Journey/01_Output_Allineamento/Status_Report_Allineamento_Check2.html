Status Report Allineamento Check 2

Questo documento riassume lo stato dell'arte dello studio e l'allineamento tra FSSO, i fondamenti di rete CCNA e i concetti VPN.

1. FSSO (Fortinet Single Sign-On) - Recap

  • Architettura a due DC: Imprescindibile per l'Alta Affidabilità. Richiede un DC Agent su ogni server per non perdere alcun log di autenticazione.
  • Collector Agent: Server centrale che mappa IP e Utenti (usa la porta TCP 8000 verso il FortiGate e TCP 8002 dai DC).
  • Push vs Polling:
    • Push: Il DC Agent invia l'evento al Collector Agent in tempo reale.
    • Polling: Il Collector o il FortiGate interroga attivamente i DC (tramite WMI o WinSecLog) per sapere chi si è loggato.

2. Fondamenti CCNA applicati al Design

  • VLAN e Domini di Broadcast: Il traffico è diviso fisicamente e logicamente. Separando i Server (VLAN 10) dagli Utenti (VLAN 20) si riduce il traffico broadcast e si limitano i rischi di propagazione malware verso i server critici.
  • Inter-VLAN Routing: Le macchine su reti diverse (es. 192.168.1.0/24 e 10.0.0.0/24) necessitano di un router per comunicare. Il FortiGate svolge questo ruolo, instradando e contemporaneamente ispezionando il traffico.
  • Default Gateway: La porta d'uscita per i dispositivi della rete. I PC puntano a 192.168.1.1 (FortiGate), i Server a 10.0.0.1.
  • NAT / PAT: Il FortiGate maschera gli IP privati interni dietro l'unico IP pubblico WAN (1.1.1.2) per permettere la navigazione sicura su Internet.

3. Integrazione tra FSSO e VPN

VPN Remote Access (Smart Working)

L'utente usa il FortiClient per collegarsi da remoto. In questo scenario l'FSSO solitamente non è necessario. Il FortiGate richiede username e password all'avvio del tunnel VPN (interrogando direttamente l'Active Directory via protocollo LDAP) e associa l'identità all'IP della pool VPN appena assegnato, applicando le policy di conseguenza.

VPN Site-to-Site (Collegamento Filiali)

Esiste un tunnel IPsec costante tra la Sede Centrale e la Filiale (es. rete 172.16.x.x). Gli utenti in filiale fanno il login sul Domain Controller della Sede attraverso il tunnel. In questo caso l'FSSO è perfetto: il DC Agent legge l'evento di login e informa il FortiGate della Sede, che applicherà le restrizioni corrette all'IP dell'utente come se si trovasse nella LAN locale.
