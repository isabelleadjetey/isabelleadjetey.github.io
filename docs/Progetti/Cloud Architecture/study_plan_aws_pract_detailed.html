Case Study AWS: Architettura "Kitchen Manager"

OBIETTIVO DI STUDIO: Questo documento analizza l'architettura reale del progetto "Kitchen Manager" (React, Django, PostgreSQL) mappandola sui concetti teorici dell'esame AWS Cloud Practitioner (CLF-C02). Capire un'architettura reale è il modo migliore per fissare in memoria i concetti cloud-native per superare l'esame.

1. Livello Frontend (S3 + CloudFront)

Il Ruolo dei Servizi

  • Amazon S3 (Simple Storage Service): Ospita i file statici compilati (HTML, CSS, JS creati da React/Vite) usando la feature Static Website Hosting. È una soluzione Serverless, si paga solo per lo storage allocato e i trasferimenti (OpEx).
  • Amazon CloudFront: È la Content Delivery Network (CDN) globale di AWS. Memorizza in cache le pagine web nelle Edge Locations (data center periferici vicini agli utenti), riducendo drasticamente la latenza ("Go global in minutes").
  • AWS WAF (Web Application Firewall): Collegato a CloudFront per filtrare traffico malevolo e attacchi comuni prima ancora che tocchi i server di backend (es. difende da SQL Injection o Cross-Site Scripting a Layer 7).
💡 Focus Esame Cloud Practitioner: Perché usare S3 per siti statici invece di un classico server EC2? Perché S3 offre scalabilità infinita "out of the box", non richiede patch o aggiornamenti del sistema operativo (ricade nella Security OF the Cloud) ed è estremamente più economico e durevole (99.999999999% durability).

2. Livello Backend (PaaS con Elastic Beanstalk)

Il Ruolo dei Servizi

  • AWS Elastic Beanstalk: Servizio PaaS (Platform as a Service). Tu carichi il codice (es. Python/Django), e AWS gestisce automaticamente sotto il cofano: l'allocazione delle istanze virtuali Amazon EC2, il bilanciamento del carico (Elastic Load Balancing - ELB), l'Auto Scaling (per reagire ai picchi) e il monitoraggio (tramite CloudWatch).
💡 Focus Esame Cloud Practitioner: Elastic Beanstalk è la risposta perfetta alla domanda: "Quale servizio permette agli sviluppatori di fare deploy rapido focalizzandosi solo sul codice senza doversi preoccupare dell'infrastruttura sottostante?". È il concetto chiave del PaaS: "Increase speed and agility".

3. Livello Dati (Amazon RDS)

Il Ruolo dei Servizi

  • Amazon RDS (Relational Database Service): Servizio per database SQL completamente gestito. Nel nostro caso ospita il motore PostgreSQL.
  • Security Groups & VPC: RDS è posizionato in subnet private all'interno della Virtual Private Cloud (VPC) dell'azienda. L'accesso è consentito esclusivamente alle istanze EC2 di backend sulla porta 5432, seguendo le stringenti regole dei firewall virtuali (Security Groups) applicando il Principio del privilegio minimo (Least Privilege).
💡 Focus Esame Cloud Practitioner: Qual è il vantaggio di usare RDS gestito rispetto ad installare tu PostgreSQL a mano su una tua istanza EC2? RDS automatizza tutti i task noiosi di amministrazione del database: backup automatici, snapshot, patch del sistema operativo del DB, e ti offre failover immediati con l'opzione Multi-AZ. Tu ti occupi solo dei dati e di ottimizzare le query.

4. Disaccoppiamento e AI (SQS, Lambda, Secrets Manager)

Il Ruolo dei Servizi

  • Amazon SQS (Simple Queue Service): Servizio di accodamento messaggi. Viene usato per separare (disaccoppiare) l'app web principale (veloce) dall'elaborazione pesante e potenzialmente lenta dell'Intelligenza Artificiale (Google Gemini).
  • AWS Lambda: Servizio di calcolo computazionale Serverless (FaaS). Elabora i messaggi prelevati da SQS ed esegue le chiamate API verso l'AI esterna. Paghi rigorosamente solo per i millisecondi in cui il codice viene eseguito, zero spese per l'inattività.
  • AWS Secrets Manager: Protegge i segreti (come le password o le API Key di Gemini). Le chiavi sensibili non vengono MAI scritte direttamente nel codice (hardcoded), ma recuperate in modo crittografato e sicuro in tempo reale dalle istanze Lambda.
💡 Focus Esame Cloud Practitioner: SQS è l'emblema del termine "Decouple" (Disaccoppiamento) e della "Fault Tolerance". Se il sistema AI esterno cade, rallenta, o se ci sono picchi immensi di traffico inaspettati, i messaggi/task vengono accodati in sicurezza su SQS senza bloccare, affaticare o far crashare l'intera app Kitchen Manager.

5. Compliance e Security Posture (IAM & Well-Architected)

  • AWS IAM (Identity and Access Management): Gestisce e centralizza chi può fare cosa (Authentication & Authorization). All'infrastruttura Kitchen Manager vengono applicate Policy specifiche basate sui Ruoli IAM (IAM Roles, assunti in modo temporaneo da EC2 e Lambda), anziché usare chiavi d'accesso statiche.
  • AWS Well-Architected Framework: Questa architettura rispetta in pieno i pilastri dettati da AWS: Operational Excellence (uso di servizi PaaS gestiti), Security (VPC chiuse, WAF per frontend, Secrets Manager), Reliability (Auto-scaling per l'elasticità, SQS per evitare rotture, RDS Multi-AZ) e Performance Efficiency (CloudFront globale, Lambda scalabile).
